# 教师课程改革证据台

整理教师培养方案、实践证据和持续发展之间的关系,为培养方案评审提供证据缺口图,而不是一张"已经开设AI课程"的完成表。

## 领域资料

仓库中的资料分为契约(`contracts/`)与样例(`fixtures/`)两部分,代码负责读取、校验并据此生成证据台视图。所有示例均为虚构数据,不含真实个人信息、账号或访问凭据。

| 资料 | 契约 | 内容 |
| --- | --- | --- |
| 能力框架 | `contracts/competencies.schema.json` | 各项能力所需的达成通道:知识学习、实践实习、导师观察、毕业后研修 |
| 历次方案 | `contracts/plans.schema.json` | 各届培养方案、AI课程策略(独立设课/融入现有课程)与学分规则变化 |
| 课程目录 | `contracts/courses.schema.json` | 校内课程及其支撑的能力通道 |
| 学生名册 | `contracts/students.schema.json` | 化名学生及其入学、毕业适用的方案 |
| 证据材料 | `contracts/evidence.schema.json` | 课程修读、工具演示、实习任务、导师观察、毕业后研修 |
| 角色范围 | `contracts/roles.schema.json` | 评审专家、教务管理员、课程负责人、实习导师的权限 |
| 十国比较 | `contracts/comparison.schema.json` | 十国制度背景维度、AI课程策略与可借鉴条件 |

## 核心规则

- 多项材料可以共同证明一项能力:按达成通道汇总,每个必需通道至少有一项合格证据。
- 一次工具演示不得冒充实践达成:`tool_demo` 只属于知识层面,永远不计入实践通道。
- 方案并行评审不能越过权限:角色只能查看评审范围内的方案。
- 学生隐私只在授权范围内使用:未授权角色只能看到汇总计数,看不到化名个体记录。
- 学分规则变化产生补修名单:按旧规则入学、按新方案毕业的学生需补修差额学分。
- 国外案例按制度背景借鉴:本校制度背景满足案例的借鉴条件时才可引用,否则逐维度列出差异。

## 证据台

```sh
npm test                              # 校验样例资料与全部业务规则
npm run board -- program_admin        # 教务管理员视角的完整证据台
npm run board -- reviewer 2025        # 评审专家视角,只看2025届(越权届别不出现)
node src/board.js mentor              # 实习导师视角,仅见被指导学生的发展路径
```

证据台按届呈现:改革影响、各能力覆盖率、未补齐的证据、待补修名单、可借鉴的国外案例,以及从职前学习延续到入职发展的真实路径。
